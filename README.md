# PDD EZ — 拼多多补货排期助手 v1.4.7

拼多多商家后台的桌面端库存管理工具。截图 OCR 识别订货管理页面，自动计算补货时间和数量，导出 Excel。

## 功能

| 功能 | 说明 |
|------|------|
| **截图识别** | 一键截取 PDD 商家后台，AI 自动提取商品/库存/销量 |
| **📥 表格导入（新）** | CSV/XLSX 结构化导入（GBK/UTF-8 编码自动探测），列映射预览可改，复用同款补货计算管线——非 PDD 表格也能用；生成导入模板 |
| **📈 历史趋势（新）** | 识别/导入数据本机 SQLite 历史库（不上传）；按日/地区汇总与单商品库存趋势折线，双阈值自动清理旧数据 |
| **💰 用量明细（新）** | API 消耗实时显示（本次/本月），今日/本周/本月/总计聚合 + 按模型/按用途分布；价格表自填（元/百万 token）估算费用，金额仅供参考 |
| **整表无 bbox 识别（方案A）** | 模型直接数整表行数（与实时截图同路径）——大表不再被 AI 行边界切碎导致乱数据/幻觉 |
| **全列识别** | 模型识别整张表格所有列，程序端按勾选列筛选显示（筛选是程序端行为） |
| **官方总数权威停止** | 读右下角分页栏"共有N条"，累计识别量 ≥ 官方 N 立即确认识别齐全、结束滚动，不再靠重试撞 |
| **滚动机制** | 像素验证滚动生效 + 多位置避 HUD + 网络/超时容错 + 防死滚，滚动力度自适应大表 |
| **模型分型** | OCR 专用模型（qwen*-ocr）只做文字提取、定位用通用视觉（vl/omni/glm/doubao），按能力各司其职 |
| **JSON 健壮性** | 输出 token 按模型分档、截断自动捞回完整行、失败现场落盘可溯源、弱模型不 400 |
| **双模型验证** | 主+副模型交叉比对，不一致标 ⚠；副模型为 OCR 专用时自动跳过验证（不兼容输出） |
| **页面状态机** | 省份开始前检测登录过期/验证码/弹窗/空白，异常自动处理或跳过 |
| **补货排期** | 自动计算补货时间和建议数量（红→立刻、黄→近期、绿→安全） |
| **多地区管理** | 按发货地区分类，批量识别多省份数据独立不混算 |
| **AI 智能定位** | 唯一定位模式，4K/带鱼屏自适应，多次采样防偏差 |
| **紧急停止** | F9 立刻中断批量（请求层取消钩子，不等超时） |
| **Excel 导出** | 结果追加到 PDD补货记录.xlsx，每次导出建一个带时间戳的 Sheet（防重名），地区作为行内首列 |

## 使用方法

1. 双击 `PDD EZ.exe`
2. 打开拼多多商家后台 → 订货管理页面
3. 点 **实时截图**，窗口最小化后自动截屏识别（最小化最多 2 秒自动恢复）
4. 确认数据无误 → 点 **刷新计算**
5. 导出 Excel

## 模型配置

- **设置 → API 管理**：配置主模型。推荐通用视觉模型：`qwen3-vl-plus` / `qwen3-vl-max`（准确率与结构化 JSON 输出稳定性最佳）、也可用 qwen3-omni-flash / glm-4.6v / Doubao-Seed 系列
- **OCR 专用模型**（qwen3.5-ocr / qwen-vl-ocr 系列）：只做文字提取，数字逐位更准；注意它**不能做定位/结构化 JSON**，配置为主模型时定位会切副模型
- 模型能力分型：定位/状态机/异常检测自动走通用视觉模型（§2 规则）
- 双模型验证的副模型请用同为"能输出表格 JSON"的模型（vl/omni 系）；配了 OCR 专用模型程序会自动跳过验证并提示

## 批量识别

- **设置 → 校准**：AI 智能定位（自动识别按钮坐标，唯一模式）
- 批量识别勾选 **🛡 双模型验证**：识别更准，但耗时约翻倍
- 滚动加载：右下角"共有N条"为权威总数，累计识别量达 N 自动结束；每行按 sku_id 权威去重（多仓库各自保留）；多省份数据独立不混算
- 网络抖动/模型处理大图超时自动容错重试，不提前误判结束
- **F9 紧急停止**：立刻中断当前识别，不等 API 超时
- 识别失败会明确提示原因，不再静默卡死

## 表格导入（非 PDD 数据源）

- 主页 **📥 导入表格**：支持 CSV（GBK / UTF-8-BOM / UTF-8 自动探测）与 XLSX（上限 1 万行）
- 首次使用点对话框里的 **生成模板**，按模板列名填好即可自动识别列映射
- 列映射预览可手动调整；缺商品名/库存/销量列会显式拒绝（不瞎猜），导入后逐行报告错误/警告
- 导入数据与截图识别走同一套补货计算与 Excel 导出管线；无"销售区域"列时归入当前地区

## 历史趋势与用量（v1.4.7 新增）

- **历史趋势**：导航页 `📈 历史趋势`——按日/地区汇总（商品数/预警数/库存合计），双击行看当日明细，再双击看单商品库存折线。地区 tab 行尾「📈 历史」按钮保留为导航页快捷入口。数据仅保存在本机（打包版在 `%APPDATA%\PDD补货助手\history.db`），不上传；默认保留 180 天 / 20 万行，可「清空全部历史」
- **用量明细**：工具条实时显示本次/本月消耗；导航页 `💰 用量明细`（原 API 设置页入口已移除）—— 4 档聚合（今日/本周/本月/总计）、按模型/按用途分布，并在价格表里填官方刊例价（元/百万 token，图片价按张）让估算更准
- 费用口径：带 `~` 前缀的行为兜底估算（不计费）；价格未配置显示 `?`；**金额仅供参考**，以提供商账单为准
- 删除地区时可选「删除并清除历史」或「仅删配置保留历史」

## 公式

```
补货时间 = 库存 ÷ 当天销量 - (运输天数 + replenishment_offset)
补货量 = 日销量 × 8
```

- `replenishment_offset` 默认 1，可在 `settings.json` 配置

| 补货时间 | 颜色 | 行动 |
|---------|------|------|
| ≤ 0 | 🔴 红 | 立刻补货 |
| 1 - 2 | 🟡 黄 | 近期补货 |
| > 2 | 🟢 绿 | 暂不补 |

## 打包

```bash
pip install pyinstaller openpyxl pillow numpy opencv-python pyautogui pyperclip pygetwindow
pyinstaller "PDD补货助手.spec"   # 主程序 onedir
pyinstaller updater.spec        # 更新器
python _build_update_zip.py     # 增量更新包（git diff 驱动，基准 = 最近 ≤ 当前版本 tag）
```

输出在 `dist/PDD EZ/`（全量 ~79MB）+ `dist/PDD_EZ_v<版本>.zip`（全量安装包）与 `PDD_EZ_v<版本>_update.zip`（增量包），均带 .sha256。发布走 GitHub Release（`gh release create vX.Y` 传资产，更新器自动检测最新版）。
