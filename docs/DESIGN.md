# PDD EZ 设计标准（阿洋拍板 · 防曲解宪法）

> **本文档是设计标准的唯一权威来源。** 任何会话/开发者/审查者修改代码前必须先读本文档。
> 违反标准的改动 = bug，即使"看起来能跑"。
> 历史教训：多会话协作中，曾因上下文丢失导致设计被曲解（见 §8 回归记录）。

---

## §1 核心架构：全列识别 + 程序端筛选（最高标准）

**模型只负责"完整抄表"，程序负责"筛选"。**

- OCR 调用点**一律 `columns=None`**（全列）：整表识别（`ocr_table`）、行级切分（`ocr_table_row_split`）、双模型（`ocr_dual_verify_generic`）、探测列（`_probe_columns`）全部如此。
- **禁止**把勾选列（selected）/探测列（all）清单丢给模型当 JSON key 筛选条件。
- 模型输出 `{表头列名: 单元格原文}`，key 必须是**模型从图中抄的表头列名**。
- 程序端 `parse_items_generic` + `mapping` 做字段提取（name/stock/sales/region/warehouse/sku_id），`_raw` 保留全列原文。
- GUI 动态列渲染（`_render_tree`）按勾选列显示——这是**程序端**行为。

**为什么**：勾选列漏配（如仓库信息）→ 丢列；列名对齐交给模型 → 串列（值错位）。

**实现位置**：`ocr.py: ocr_table / ocr_table_row_split / ocr_dual_verify_generic`、`gui.py: _ocr_generic_to_items / _fill_from_ocr`、`settings_ui.py: _probe_columns`。

## §2 模型选型规则（阿洋 8/6 拍板）

| 任务类型 | 用哪个模型 |
|---------|-----------|
| 文字识别（表格抄写、OCR） | 主模型；配置了 OCR 专用模型（qwen*-ocr）时优先它（数字更准） |
| 定位/状态机/异常检测/列名探测（结构理解） | 通用视觉模型（`prefer_general`） |
| 主模型是 OCR 专用、需要定位时 | 副模型（用户配置的通用视觉） |
| 主副都无法定位 | **明确报错，绝不静默回退硬编码模型**（额度/权限不可控） |

**实现位置**：`vision.py: _pick_vision_model / _call_vision_api`、`ocr.py: _ocr_api_call(prefer_general)`。

## §3 多省份/多地区数据独立性

- 每省份识别结果独立：`round_items` 按省份隔离，`cache[region]` 独立缓存。
- 切地区必须同步重建 rows（`_switch_region`），禁止上一地区 rows 覆盖当前地区缓存。
- 每商品用自己的 region 查运输时效（`_calc_from_items` 逐商品 `item.get('region')`）。
- 批量识别完成表格只显示第一个地区，其余走地区 tab（`_fill_from_ocr` 按地区分组）。

## §4 失败哲学：宁可显式失败，不猜测

- 定位失败 → 明确日志 + 跳过/提示，**不猜测位置乱点**（v1.3 起无预设坐标兜底）。
- OCR/API 失败 → 明确提示原因，不静默卡死。
- 识别失败保留现场截图（`_prov_fail_*.png`）供人工排查。

## §5 安全底线

- 更新器：`target_dir` 必须是 PDD EZ 程序目录才允许更新；回滚改名 `_stale_*` 保留，**绝不 rmtree 用户目录**；SHA256 校验；安全解压。
- 敏感文件（settings.json/keys.*/config.ini/.env）**绝不进发布包和 git 历史**；key 从配置/环境变量读，不硬编码。
- 推 git 前检查历史无 key 残留。

## §6 版本规则

- **主版本永远是 v1.4 系列（v1.4.x），没有 v1.5**。功能迭代/修复都在 v1.4 内。
- 小版本号（v1.4.1 / v1.4.2…）用于发布轮次标记（阿洋拍板 8/12：标记改为 1.4.1）。
- 发布物：`dist/PDD EZ/`（onedir，固定名 `PDD EZ.exe`）+ 全量 zip + 增量 zip
  （git diff 基准 = 最近 ≤当前版本的 tag，防历史大版本 tag 劫持）。

## §7 其他拍板项

- AI 智能定位是**唯一模式**（绝对坐标已移除，v1.3 起）。
- 双模型验证：主+副交叉比对，不一致标 ⚠；副模型失败降级单模型但必须提示。
- 页面状态机：省份开始前检查 normal/login/captcha/modal/empty，login 中止批量，异常跳过省份。
- 滚动去重三路：ID 精确 / ID 近匹配(≤2)+name 前6字 / name 强相似(前6字+距离≤6)，同名不同规格保留。
- 列名匹配：`name` 永不模糊匹配；其他字段模糊仅限编辑距离≤2 且前 3 字相同。
- 实时截图窗口恢复：主线程 2 秒无条件恢复（最小化最多 2 秒）。

## §9 审查清单（改代码前自问）

1. 这个 OCR 调用传了列清单吗？（§1 禁止）
2. 定位/状态机任务用的是通用视觉吗？（§2）
3. 多省份数据会不会串？（§3）
4. 失败是显式提示还是静默？（§4）
5. 有没有碰敏感文件/历史？（§5）
6. 版本还是 v1.4 吗？（§6）
