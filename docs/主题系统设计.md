# PDD EZ — 主题系统完整设计（颜色 + 组件 + 装饰全跟随）

> 目标：让每套主题都是**完整设计**，而不只是换背景色。
> 切主题时，黄色通栏 / 切角按钮 / 表头黄线 / 侧边黄线 / FREE-PRO 角标 / 主题卡片全部随主题重绘。
> 本文档是方案 + 实施清单，逐行可对照 gui.py / settings_ui.py / config.py。

---

## 1. 现状与问题

- `config.py::THEMES` 只有 `C_*` 语义色 token（约 12–14 个）。
- `gui.py` 大量硬编码终末地黄黑色（`#FFE600` / `#111111` / `#333333` / `#E0E0E0`），集中在：
  - 顶部黄通栏 + 斜切几何块 + 版本角标（`_redraw_deco`）
  - 切角按钮 `_btn_colors()` / `_CanvasBtn._colors`
  - 表头黄线、列分割线、结果区黄线
  - FREE/PRO 胶囊角标（`_refresh_model_badge`）
  - 导航按钮 accent 边条
- 这些元素大多打了 `_skip_theme = True`，或本身是 Canvas item（walk 读不到 fill/outline），
  导致主题切换时它们永远停留在机能黄 → **「切主题 = 工业风换背景色」**。

### 三个根因（对号入座）

1. **`_skip_theme` 钉死了装饰**：`_apply_theme` 三遍 walk 遇到该标记一律跳过。
   注释「黄通栏是设计元素，主题切换不刷白」——正是这条规则让其他主题只剩背景色。
2. **切角按钮配色是构造时快照**：`_btn_colors(kind)` 返回硬编码 dict 后复制进 `_CanvasBtn`，
   `_apply_theme` 不碰它们。
3. **Canvas 自绘元素不在 walk 能力内**：`_walk_color` 只能读 Canvas 的 `bg`（画布底色），
   读不到 item 的 `fill/outline`。Canvas 装饰必须靠**重绘**，不能靠 walk。

> 顺带发现：`gui.py:460 / 526 / 605` 的 `_skip_theme` 是**多余**的——
> 它们的 bg 本就是 `C_BORDER / C_ACCENT` 这类 C_ token，删掉 skip 后 walk 的旧→新映射会自动换色。
> 属「一刀切全 skip」的误伤。

## 2. 目标架构：三层 token

```
THEMES[name] = {
    label / desc,
    C_*            ← 语义色（现有层，保留，_apply_theme 的 setattr + walk 逻辑零改动）
    components:    ← 组件 token（新增）：btn / table / pill / field / nav / card / on_accent ...
    decor:         ← 装饰 token（新增）：topbar / section / result ...
}
```

原则：

- **装饰和组件也是 token**，每套主题各自给完整值，不从「机能黄」继承。
- **几何/字体也可 token**（切角像素 `btn.corner`、通栏高度、黄线高度），
  这样「组件样式」真正全跟随，甚至支持「直角主题」。
- 读色统一走 resolver：`self.tc('btn.primary.bg')` 或 `self.tc('C_BG')`（向后兼容）。

    "components": {"on_accent": "#111111", "on_primary": "#FFFFFF",
                   "btn": {}, "table": {}, "pill": {}, "field": {}, "nav": {}, "card": {}},
    "decor": {"topbar": {}, "section": {}, "result": {}},

def _merge_theme(spec):
    """老主题缺键回退默认，保证不崩"""
    import copy
    base = copy.deepcopy(_DEFAULTS)
    for k in ("components", "decor"):
        base[k].update(spec.get(k, {}))
    out = {**spec, "components": base["components"], "decor": base["decor"]}

## 4. 机制层：Tkinter 三件套

### 4.1 Token Resolver（唯一取色入口，向后兼容）

```python
# App 上
def tc(self, path, default=None):
    """读组件/装饰 token：'btn.primary.bg' 或 'C_BG' 都支持，缺省兜底"""
    if path.startswith('C_'):
        return getattr(self, path, default)
    node = self._theme_spec
    for part in path.split('.'):
        if isinstance(node, dict) and part in node:
            node = node[part]
        else:
            return default
    return node
```

- `_apply_theme` 里新增一行 `self._theme_spec = _merge_theme(theme)`。
- 现有 `setattr(self, k, v)`（C_*）照旧 → `_walk_color` / `_walk_force` 逻辑零改动。

### 4.2 绘制函数（建 UI 与重绘统一）

每个装饰元素一个绘制函数，内部全部读 `self.tc(...)`：

```python
def _redraw_deco(self, event=None):
    try:
        self._deco.delete('deco')
    except Exception:
        return
    w = self._deco.winfo_width() if event is None else event.width
    if w < 200:
        return
    tb = self.tc('decor.topbar')
    self._deco.create_polygon(w - 360, 0, w - 60, 0, w - 360, 66,
                              fill=tb['block1'], outline='', tags='deco')
    # ... 其余 item 同理
    self._deco.create_polygon(w - 190, 10, ..., fill=tb['ver_bg'],
                              outline=tb['ver_edge'], width=1, tags='deco')
    self._deco.create_text(w - 135, 24, text="V" + VERSION.upper(),
                           fill=tb['ver_fg'], ..., tags='deco')
```

### 4.3 重绘注册表（取代 `_skip_theme`）

```python
# __init__ 里
self._theme_redraws = []

def _register_redraw(self, fn):
    self._theme_redraws.append(fn)

# _apply_theme 末尾（ttk 之后）
for fn in self._theme_redraws:
    try:
        fn()
    except Exception:
        pass
```

**分工原则：Canvas 装饰走重绘注册表；普通 tk.Frame/Label 去掉 skip 走现有 walk。**

## 6. Tkinter 实现细节（易踩坑）

### 6.1 `_CanvasBtn.retheme()`

```python
def retheme(self):
    c = self._colors = self.owner.tc(f'btn.{self._kind}') if self._kind else self._colors
    self._apply()   # 复用现有 _apply 重画 poly + text
```

`_CanvasBtn` 需持有 `owner` 引用（或 `tc` 函数），构造时
`self.owner._register_redraw(self.retheme)`。

### 6.2 Canvas 装饰统一「tag + 重绘函数 + 复用 <Configure>」

现有 `_redraw_deco` 已是正确模式（`delete('deco')` → 按宽度重画）。主题化只需换色值，
并把签名改成 `_redraw_deco(self, event=None)`，内部用 `winfo_width()` 兜底（重绘表调用时无 event）。

### 6.3 `_refresh_model_badge` 的重建时机

它每次切页重建 pill。改后读 `pill.*` token，并在重绘表里也注册一次
（内部 delete/重建，天然幂等）。

### 6.4 对比度

每套主题提供 `on_accent` / `on_primary` 前景 token，避免「黑字配深色 accent」。
极简白 accent 是蓝 `#2563EB` → primary 按钮 `fg=#FFFFFF`，hover 深一档。

### 6.5 防 TclError

重绘函数入口统一 `try/except`（控件可能在销毁中），现有代码已有该模式，保持。

## 9. 一句话总结

把「黄通栏是设计元素，主题切换不刷白」改成「黄通栏是设计元素，每个主题都给它配一套值」；
把 Canvas 装饰从 walk 的死角里拿出来，统一走「token 读取 + 注册重绘」。
这样每套主题才是完整设计，而不是「工业风换背景色」。
